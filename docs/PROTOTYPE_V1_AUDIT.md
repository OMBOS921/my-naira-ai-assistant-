# NairaLLM Prototype V1 — Comprehensive Technical Audit

**Document Date:** August 2026  
**Audited Target:** NairaLLM Prototype V1 Subsystem (`NairaLLM/`)  
**Scope:** Architecture, Tokenizer, Training Pipeline, Checkpoint, Dataset, Evaluation Suites, Tool Protocol, and Integration Workflows.

---

## Executive Summary

NairaLLM Prototype V1 successfully establishes the foundation for a self-owned, lightweight causal language model and integration ecosystem for Naira OS. It operates in pure Python/NumPy on CPU without mandatory heavy GPU or PyTorch dependencies, adheres strictly to real Naira OS schemas and interfaces, and provides structured tool calling protocols.

However, an honest audit reveals that **Prototype V1's benchmark score and demonstration largely reflected deterministic integration/workflow orchestration rather than autonomous model generalization**. The seed dataset was limited to 16 samples, and prior benchmark tests validated tool execution and mocked adapters rather than testing whether the neural weights themselves chose correct tools and synthesized responses on unseen prompts.

---

## 1. What Is Genuinely Implemented

| Component | Status | Implementation Details |
| :--- | :--- | :--- |
| **Neural Architecture** | ✅ Genuine | Decoder-only Causal Transformer with Rotary Position Embeddings (RoPE), RMSNorm pre-normalization, SwiGLU gated FFN, and causal multi-head self-attention. Implemented both in PyTorch (`naira_transformer.py`) and zero-dependency Pure NumPy (`numpy_backend.py`). |
| **Tokenizer** | ✅ Genuine | Byte-Level BPE tokenizer with 11 custom special tokens (`<|pad|>`, `<|endoftext|>`, `<|system|>`, `<|user|>`, `<|assistant|>`, `<|tool_call|>`, `<|tool_result|>`, `<|thought|>`, `<|plan|>`, `<|verify|>`, `<|unk|>`). Supports multilingual UTF-8 (English, Hindi Devanagari, Hinglish). Supports both Rust `tokenizers` and pure-Python fallback. |
| **Training Pipeline** | ✅ Genuine | Adam optimizer with forward/backward cross-entropy loss, token embedding updates, gradient computation, and `.npz` weight persistence (`train_numpy.py` & `train.py`). |
| **Model Runtime** | ✅ Genuine | Autoregressive text generation with temperature, top-k, top-p sampling, stop token halting, and structured tool call extraction (`naira_runtime.py`). |
| **Tool Protocol** | ✅ Genuine | Schema validator against actual Naira OS tools (`pc_system_settings`, `pc_mouse`, `pc_keyboard`, `pc_clipboard`, `browser_search`, `browser_navigate`, `remember_fact`, `search_memory`, etc.) with security permission gating. |
| **Integration Adapters** | ✅ Genuine | `NairaLLMAdapter` conforming to `ResponsePipeline` contracts, plus modular workflow wrappers for Memory, Browser Research, Coding Agent Handoff, and Bounded Proactive Behavior (Autonomy Levels 0–5). |

## 2. What Is Only Integration / Workflow Code

The following capabilities are provided by surrounding Python integration code, not by neural model reasoning:
- **Autonomy Policy & Safety Gate:** Bounded execution enforcement (Level 2 confirmation requirement, risk checks) is enforced by `BoundedProactiveWorkflow` and `ToolProtocol.security_checker`.
- **Tool Dispatch & Subsystem Execution:** Actual execution of commands on PC, Browser, Memory SQLite, or Coding Agent is executed by Python orchestration.
- **Workflow State Machine:** Multi-turn loop (User -> LLM -> Tool Call -> Subsystem -> Tool Result -> LLM Synthesis) is orchestrated by workflow classes (`MemoryWorkflow`, `BrowserResearchWorkflow`, `CodingHandoffWorkflow`).

---

## 3. What Is Actually Generated by the Trained Model

In Prototype V1:
- **Generation Output:** The trained model (`numpy_model.npz`, 64 hidden dim, 2 layers, 2 heads) generates token sequences based on learned autoregressive probabilities.
- **Trained Representations:** On seed patterns that closely matched the 16 training examples, the model learned prompt prefixes and token transitions for basic greetings and tool formatting.
- **Limitations:** When presented with unseen vocabulary, colloquial Hindi/Hinglish syntax, or multi-step requests with novel phrasing, the 16-sample model frequently degraded or produced incomplete tool calls because it had not learned generalized representations across diverse expressions.

---

## 4. Which Benchmark Results Depended on Deterministic / Hard-Coded Logic

In `challenge_suite.py` (V1):
1. **Tool Selection (`C04_TOOL_SELECTION`):** Directly passed a hard-coded dictionary `{"name": "pc_system_settings", "arguments": {"setting": "volume", "value": 50}}` to `ToolProtocol.validate_tool_call()`. The model was **not** asked to generate the tool call from user input.
2. **Tool Verification (`C05_TOOL_VERIFY`):** Directly instantiated a `ToolCall` and passed it to `protocol.execute_validated_call()`.
3. **Memory Write (`C06_MEMORY_WRITE`):** Hardcoded `wf.remember("User preferred font size is 14", topic="editor_preference")`, forcing the topic argument.
4. **Memory Recall (`C07_MEMORY_RECALL`):** Relied on workflow wrapper logic and only checked `len(resp_text) > 0`.
5. **Browser Research (`C08_BROWSER_RESEARCH`):** Directly called `wf.research()`.
6. **Coding Handoff (`C09_CODING_HANDOFF`):** Directly invoked `wf.plan_and_execute_coding_task()`.
7. **Bounded Proactive (`C11_BOUNDED_PROACTIVE`):** Evaluated Python class `AutonomyLevel.LEVEL_2_CONFIRM` without testing model-driven urgency classification.

> **Verdict:** The V1 challenge suite was an **Integration Verification Suite**, not a **Model Intelligence Benchmark**.

---

## 5. Current Model Limitations

1. **Parameter Scale & Capacity:** Current model uses $d_{model} = 64$ ($d_{ff} = 128$), 2 decoder layers, 2 attention heads. While fast, capacity is limited for deep semantic disambiguation.
2. **Context Window:** Max sequence length is configured to 256 tokens. Multi-turn trajectories with large tool outputs need concise representation.
3. **Pure Output Regularization:** Without exposure to failure and recovery patterns, raw generations on novel phrasing can suffer from token repetition or premature EOS.

---

## 6. Current Dataset Limitations

1. **Extremely Small Size:** Only 16 seed samples in V1 `initial_dataset.jsonl`.
2. **Language Imbalance:** 11 English samples (68.75%), 3 Hinglish (18.75%), 2 Hindi (12.5%).
3. **Zero Negative / Safety Refusal Diversity:** Only 1 safety refusal example.
4. **Limited Tool Coverage:** Only 5 tools exercised out of the 30+ registered Naira OS tools.
5. **No Trajectory Depth:** Most samples were single-turn tool calls rather than multi-step chains (User -> Model -> Tool -> Result -> Reflection -> Verification).

---

## Next Steps for V1.1

1. **Model-Only Generalization Benchmark:** Evaluate model decisions on **unseen** prompts without hard-coded test helpers.
2. **Dataset Expansion:** Scale from 16 to **500+ curated, validated samples** across all 18 families and 3 languages (English, Hindi, Hinglish) with real Naira OS tool schemas.
3. **Model Retraining:** Train NairaLLM V1.1 checkpoint and record loss, perplexity, and generalization metrics.
4. **End-to-End Live Validation:** Validate real tool execution, memory grounded recall, browser research, coding planning, and bounded proactive notifications driven by neural model decisions.
